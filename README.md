# Travel CRM


Курсовой проект по дисциплине ПКИС, группа ЭФМО-01-25.


**Тема:** «Создание программного решения для автоматизации процесса управления клиентскими отношениями в туристической компании».


## Назначение


Веб-сервис для работы туристической компании с клиентами: ведение заявок, подбор туров по предпочтениям, управление бронированиями, учёт платежей, история общения и базовая отчётность.


В учебной версии используется тестовый каталог и заглушка платёжного сервиса. Бронирование у поставщика менеджер выполняет вне CRM и вносит его ответ в систему.


## Текущий статус


Работают серверная авторизация и клиенты с интерфейсом: список, поиск, создание, изменение, проверка дублей и прав. Добавлены дизайн-система, генерация TypeScript-типов, страница профиля и запуск Vue через nginx в Compose. API заявок, истории, ответственных и каталога готовы для подключения интерфейса #13/#30; правила — в [requests-integration.md](docs/api/requests-integration.md) и [tours-integration.md](docs/api/tours-integration.md). Дополнительные данные профиля ожидают API по #48. Подборки, брони и платежи ещё не реализованы.

Показ назначен на 04.12.2026. Порядок реализации — в [плане #46](https://github.com/d1vide/travel-crm/issues/46) и [roadmap](docs/roadmap.md): сначала заявки #13 и каталог #30, затем подбор и бронь, затем оплата.

## Совместная работа


Задачи ведутся в [Issues](https://github.com/d1vide/travel-crm/issues). Обычные изменения выполняются в отдельных ветках, сохраняются коммитами и объединяются в main через Pull Request после проверки. Владелец и соавтор с правом записи также могут делать прямые коммиты в main. Одобрение второго участника доступно, но не обязательно. Подробности — в [правилах команды](docs/team.md).


Модель данных, переходы статусов и контракт API 0.2 зафиксированы. Типы фронтенда уже генерируются командой `npm run gen:api`. Экспорт полной спецификации из кода и оставшиеся части #26, как и CI #25, перенесены после показа. Текущие проверки выполняются локально; бизнес-права и проверки дополняются с каждым модулем.


## Запуск


Запуск по [backend/README.md](backend/README.md): `python scripts/init_env.py`, затем `docker compose up --build`. Compose содержит db, backend и web: приложение доступно на http://localhost:8080, API напрямую — на http://localhost:8000. Платёжной заглушки ещё нет; она добавляется в #15 с завершением #24.

Фронтенд запускается отдельно по [frontend/README.md](frontend/README.md) на localhost:5173 и проксирует /api на бэкенд. Для нативной разработки после подготовки PostgreSQL: `uv sync --directory backend --frozen`, затем `uv run --directory backend python -m app.bootstrap`.
