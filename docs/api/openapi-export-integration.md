# Экспорт HTTP-контракта

Из корня проекта (Python 3.12 и uv):

```sh
uv sync --directory backend --frozen
uv run --project backend python docs/api/build_openapi.py
cd frontend
npm run gen:api
```

Закоммитьте `docs/api/openapi.json` и `frontend/src/api/schema.d.ts` вместе с изменениями API. Для проверки без перезаписи:

```sh
uv run --project backend python docs/api/build_openapi.py --check
uv run --project backend python docs/api/validate_contract.py
```

Экспорт не загружает локальный `.env`, не подключается к PostgreSQL, не запускает миграции, seed или фонового работника. Работающий сервер использует тот же генератор для `/openapi.json`. Внутренний callback оплаты `/internal/payment-events` не публикуется. Health-маршруты включены отдельно от 60 бизнес-операций.

Пути, методы, operationId, параметры, тела и успешные ответы берутся из FastAPI; DTO — из Pydantic. Роли `x-roles` выводятся из зависимостей `require_roles`; общие ошибки отражают зарегистрированные обработчики. Не возвращается стандартная HTTPValidationError FastAPI: 422 использует Error. Правило контактов находится в Pydantic как `allOf + anyOf`, сохраняя общие поля объекта для TypeScript.

`backend/app/api_metadata.json` содержит только описания, FR и вымышленные примеры. При добавлении операции добавьте её аннотации по operationId. Удалённая операция с оставшимися аннотациями вызывает ошибку экспорта. Формы DTO и перечни параметров в этом файле не задаются. Имена User/UserProfile и отдельные типы статусов/действий сохраняются для потребителей контракта; определения берутся из серверных моделей. `domain.schema.json` служит проектным справочником и независимой проверкой примеров, а не источником HTTP-схем.

Пути, operationId и формат бизнес-ответов сохранены. Экспорт теперь показывает ограничения и обязательность полей фактических моделей, в том числе максимумы пагинации; health имеет типизированный ответ. Существующие экраны проходят генерацию и проверку типов. Изменение сетевого формата необходимо описывать отдельно как BREAKING.

Фронтенд продолжает использовать существующий HTTP-клиент с refresh, credentials и Idempotency-Key. Этот серверный PR не заменяет его на openapi-fetch. Генерация типов уже работает; завершение клиентской части #26 учитывается отдельно. Vite поддерживает VITE_API_TARGET, а запуск Prism описан в [обзоре API](README.md). Статический мок не воспроизводит транзакции и права.
