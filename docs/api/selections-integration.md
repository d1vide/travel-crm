# Подключение подборок — #31

Реализованы восемь операций OpenAPI: список и создание подборок заявки, карточка подборки, выдача и отзыв публичной ссылки, публичный просмотр, выбор тура и return-to-work. Использовать Selection, SelectionPage, SelectionCreate, SelectTour, PublicLink, PublicLinkInfo, PublicSelection и ExpectedVersion из сгенерированного клиента.

## Подборка и выбор

POST /api/requests/{request_id}/selections принимает текущую version заявки и непустой tour_offer_ids без повторов. Все предложения должны существовать и быть активными; порядок массива сохраняется в items.position, начиная с 0. Подборка сохраняет неизменяемые снимки OfferSnapshot: последующее изменение каталога не меняет опубликованные цены, даты и услуги. Деньги остаются строками, цена относится ко всему указанному числу туристов.

Публикация доступна ответственному менеджеру и руководителю в in_progress/offer_prepared. Успех — 201 с Selection; заявка переходит в offer_prepared, её version увеличивается, прежний выбор очищается, ссылки предыдущих подборок отзываются. После публикации перечитать Request. Бухгалтер не имеет доступа; чужие и отсутствующие подборки дают одинаковый 404.

GET /api/requests/{request_id}/selections возвращает SelectionPage: page/page_size, sort=-created_at, стабильный порядок по created_at/id. GET /api/selections/{selection_id} возвращает Selection. Старые подборки сохраняются для истории. Редактирования или удаления нет: новый состав публикуется новой подборкой. Направление, даты и количество на этапе подбора не обязаны точно совпадать с пожеланиями заявки; соответствие количества заявки, выбранного снимка и туристов проверяется при бронировании.

PUT /api/requests/{request_id}/selected-tour принимает version и selection_item_id. Это ID элемента последней подборки этой заявки, а не tour_offer_id каталога. Выбор доступен только в offer_prepared. Ответ — Request с selected_selection_item_id, selected_selection_id и selected_offer. Новый выбор повышает version; повторный выбор уже выбранного элемента с актуальной version её не меняет. Выбор записывает сотрудник после общения с клиентом: публичная страница доступна только для просмотра.

POST /api/requests/{request_id}/actions/return-to-work принимает ExpectedVersion: offer_prepared → in_progress, выбор очищается, публичные ссылки заявки отзываются. Отмена теперь доступна и в offer_prepared; cancel/resume также очищают выбор и отзывают ссылки. Ориентироваться на allowed_actions, при 409 перечитать карточку и не увеличивать version самостоятельно.

Создание подборки, выбор и return-to-work требуют Idempotency-Key UUID. Сетевой повтор сохраняет исходное тело и ключ, включая повтор после refresh. Успешный повтор не создаёт новую подборку и не повышает версию; возвращается текущее разрешённое представление исходного ресурса. Тот же ключ с другим телом — 409 idempotency_conflict. Доступ проверяется заново, в том числе после переназначения заявки.

## Публичные ссылки

POST /api/selections/{selection_id}/public-link без тела выдаёт 201 с PublicLink. Допускается только последняя подборка заявки в offer_prepared. Копировать ровно url из ответа; адрес строится сервером из PUBLIC_APP_URL, а не из заголовков запроса. В .env указать origin доступного клиенту приложения, например https://crm.example.test; для локального web по умолчанию http://localhost:8080. Путь, query и credentials в настройке запрещены. Для локального Vite origin настраивается отдельно. Существующий .env необходимо дополнить вручную при смене адреса; init_env.py его не перезаписывает.

Ссылка действует 7 дней. Каждый выпуск отзывает предыдущую ссылку этой подборки, включая истёкшую. Команда не принимает ключ повтора: не повторять её автоматически при сетевой ошибке или refresh. Если результат потерян, предложить явный перевыпуск. В БД хранится только SHA-256 токена; GET Selection возвращает лишь public_link с id, purpose=selection, expires_at и is_active, без url. После отзыва/истечения метаданные последней ссылки остаются с is_active=false. DELETE /api/public-links/{link_id} отзывает ссылку; повтор возвращает 204. Выпуск и отзыв не изменяют version заявки.

Frontend-маршрут — /public/selections/:token; API — GET /api/public/selections/{token}, без JWT. Ответ PublicSelection содержит только items (id элемента и offer_snapshot) и expires_at. Клиента, ответственного, request_id, selection_id и ID каталога в публичном ответе нет. Неверный токен, истечение, отзыв и ссылка другого назначения дают одинаковый 404. Переназначение менеджера не отзывает уже выданную клиенту ссылку; возврат в работу, отмена и замена подборки отзывают её.

Публичные ответы и страница имеют no-store/no-referrer, включая ошибки. Не сохранять токены в localStorage, аналитике, истории API или диагностических сообщениях; публичный экран не должен подключать внешние ресурсы. nginx исключает публичные URL из access/error логов, сервер маскирует путь публичного API перед access logging. При добавлении другого прокси или системы мониторинга сохранить эти ограничения.
