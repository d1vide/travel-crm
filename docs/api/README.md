# Контракт TravelCRM API

Версия 0.2 от 15.11.2026. Зафиксирован по поручению владельца проекта после самостоятельной сверки с текущим фронтендом, ТЗ и сценариями. [Результаты проверки](frontend-review.md) перечисляют покрытие экранов, исправления и необходимые изменения интерфейса. Отдельное подтверждение коллеги не заявляется.

Контракт описывает целевой API. Реализованы login/refresh/logout/me, health, клиенты #12, десять операций заявок/истории/ответственных #13, два маршрута каталога #30, три маршрута общения #16, восемь операций подборок/ссылок/выбора #31, пять операций туристов #32, пять операций бронирований #14 и пять операций оплаты #15; #33 добавляет уведомления, финансовые брони и завершение заявки (четыре операции). Инструкции подключения [клиентов](clients-integration.md), [заявок](requests-integration.md), [каталога](tours-integration.md), [общения](communications-integration.md), [подборок](selections-integration.md), [туристов](tourists-integration.md) [бронирований](bookings-integration.md) и [оплаты](payments-integration.md) описывают готовое поведение и границы следующих модулей. Дополнение по [результатам оплаты и завершению](payment-notifications-integration.md) описывает #33. Остальные операции остаются planned; у операций OpenAPI указан x-implementation-status. Runtime /openapi.json показывает реализованный поднабор и не заменяет полную спецификацию.

До появления серверных схем источники — `domain.schema.json` и реестр в `build_openapi.py`; `openapi.json` генерируется, вручную его не редактировать. Для фронтенда контрактом служит именно `openapi.json`: он импортируется в генератор TypeScript и мок без дополнительных файлов.

Когда в #7/#9 появятся Pydantic-схемы и роуты, экспорт сервера должен соответствовать этому контракту. В #26 экспорт FastAPI станет единственным источником `openapi.json`; временный генератор удаляется или заменяется экспортом. Различия в путях, operationId, required/nullable, enum, деньгах, ответах и правах рассматриваются как изменения контракта. Полные бизнес-сценарии реализуются в своих Issues.

## Общие соглашения

| Область | Правило |
|---|---|
| Адреса | Пути OpenAPI уже содержат /api, servers равен /. Сгенерированный клиент использует origin без дополнительного /api; существующий useHttp('/requests') сохраняет свой baseUrl=/api. Не добавлять /api/api |
| Поля JSON | snake_case; внутри Vue допускается явное преобразование на границе API |
| UUID | Строки, без преобразования в number |
| Деньги | Строки с двумя знаками: `"100000.00"`, валюта RUB. Сервер возвращает суммы и остатки |
| Даты/время | События — RFC 3339 UTC с Z, отображение Europe/Moscow. Даты поездки/рождения — YYYY-MM-DD без часового пояса |
| Null | Явное null для nullable; read DTO содержит required поля. Пустые контакты нормализуются в null |
| Роли | manager, head, accountant — совпадают с каркасом фронтенда |
| Авторизация | Bearer access только в памяти. AuthResult сохраняет access_token, user.id, user.full_name, user.role |
| Refresh | Cookie refresh_token: HttpOnly, SameSite=Strict, Path=/api/auth; Secure при HTTPS. Login/refresh/logout проверяют same-origin Origin; в локальном HTTP Secure опускается |
| Ошибки | `{code, message, fields: [{field, message}]}`. code из ErrorCode, сообщение по-русски; field — путь JSON, например tourists.0.birth_date |
| Списки | `{items, page, page_size, total}`; page с 1, размер по умолчанию 20, максимум 100; пустая страница — items=[] и 200. При равенстве сортировки добавляется id |
| Фильтры | Только параметры операции; неизвестные параметры/неверные значения — 422. Фильтры объединяются AND, права применяются до пагинации и total |
| Действия | allowed_actions определяет доступные сейчас кнопки; роль и статус сами по себе недостаточны. Сервер повторяет проверку при команде |
| Версии | version в read DTO и командах; у формы туристов request_version. При 409 перечитать ресурс, не вычислять следующую версию локально |
| Повторы | Idempotency-Key UUID обязателен там, где указан в OpenAPI. Повтор тела сохраняет ключ, новая команда получает новый. Повтор после refresh использует исходный ключ |
| Платёжный сервис | Создание платежа/возврата и reconcile: 202 с текущей операцией, это не успех оплаты. UI опрашивает GET; pending/processing сохраняют резерв |

Стабильные ошибки: version_conflict, invalid_transition, idempotency_conflict, duplicate_contacts, duplicate_requires_head_review, payment_limit_exceeded, refund_limit_exceeded, tourist_form_closed. Стандартные ошибки FastAPI приводятся к тому же Error с 422. Скрытый ресурс и недействительная публичная ссылка дают одинаковый 404.

Каталог: starts_from — начало тура не раньше даты, ends_until — окончание не позже даты, обе границы включены; tourist_count — точное совпадение, max_price — общая цена. Менеджеру фильтр чужого manager_id даёт 403. Остальные параметры и разрешённые сортировки перечислены в OpenAPI.

## Данные для экранов

- Request содержит краткого клиента и ответственного с именами, выбранный снимок, краткую действующую бронь, число полученных туристов и действия. Отдельные запросы за именем каждой строки не нужны.
- ClientCreate/Update выполняются после проверки дублей; совпадение подтверждается duplicate_acknowledged. При 409 перепроверить контакты, не сливать карточки автоматически.
- PublicSelection и PublicTouristForm не используют JWT и не раскрывают контакты, ответственного и ранее введённые паспорта. Публичные ответы no-store/no-referrer. Форма показывает is_editable и closed_reason.
- PublicLinkInfo показывает активность/срок. Копируется url из ответа выдачи ссылки; после потери url — явный перевыпуск с отзывом предыдущей ссылки. Автоматические сетевые повторы этой команды исключены: в БД только хеш токена.
- Полный список туристов обязателен до создания pending-брони. Форма редактируется в in_progress/offer_prepared без действующей брони; подтверждение сохраняет снимки в Booking.tourists. У pending-брони снимки могут быть пусты, исходные данные доступны сотруднику в разделе туристов.
- Менеджер получает свои платежи внутри карточки брони. Глобальные payments/refunds/financial-bookings доступны head/accountant, что совпадает с меню. FinancialBooking исключает паспорта и персональную карточку; бухгалтер имеет только чтение.
- Максимум нового платежа — Booking.available_payment_amount, а не remaining_amount: pending резервирует долг. Для возврата выбирается исходный Payment и его available_refund_amount; он равен нулю, если возврат сейчас недоступен. Старые деньги не оплачивают новую бронь.
- У Communication есть author с именем. Руководитель получает активных ответственных через users и безопасную историю AuditRecord. Отчёт возвращает отдельные суммы оплат/возвратов, при пустом периоде — нули.
- Уведомления опрашиваются раз в 15 секунд при активной вкладке. NotificationPage содержит unread_count; после переназначения ссылки на недоступные заявки убираются. Открытые pending платежи/возвраты опрашиваются раз в 5 секунд.

Входные модели выделены отдельно: нельзя отправлять read DTO целиком. ID, автор, системные даты, финансовые итоги, статусы и allowed_actions задаются сервером. Для статуса вызывается бизнес-команда. После выбора/подборки/туристов/брони/финансовой команды перечитать затронутые Request/Booking; до этого следующая запись блокируется.

Страницы фронтенда `/public/selections/:token` и `/public/tourist-forms/:token` находятся вне MainLayout; API этих страниц — под `/api/public/...`. Оплата открывается по непрозрачному payment_url заглушки: фронтенд не строит этот адрес и не подтверждает платёж по возврату браузера.

## Проверка и генерация

Из корня репозитория, Python 3.12+ и uv:

```bash
uv run docs/api/build_openapi.py
uv run docs/api/validate_contract.py
```

Генератор использует стандартную библиотеку; зависимости валидатора закреплены в скрипте. `build_openapi.py --check` проверяет актуальность без перезаписи. С установленными зависимостями допустим запуск через python.

TypeScript генерируется из openapi.json, а не написанием второго набора интерфейсов по памяти. В #26 используются openapi-typescript/openapi-fetch с сохранением refresh, русских ошибок и credentials. До сервера допустим Prism по той же спецификации. Примеры описывают отдельные DTO, а не связанную БД; статический мок не воспроизводит транзакции и переходы.

Проверенный запуск мока: `npx @stoplight/prism-cli@5.14.2 mock docs/api/openapi.json --port 4010 --host 127.0.0.1`. После переключения VITE_API_TARGET на http://127.0.0.1:4010 перезапустить Vite; /api сохраняется без rewrite. Prism не проверяет x-roles и бизнес-условия. Для сценария ошибки использовать ответ Error из спецификации через заголовок `Prefer: code=422`; собственные ошибки проверки запроса Prism могут иметь другой формат.

Изменение контракта обновляет схемы, примеры, реестр и OpenAPI в одном PR; несовместимые изменения явно помечаются. JSON Schema проверяет форму данных; права, календарные интервалы, связи, версии и суммы нескольких операций проверяются серверной логикой и интеграционными тестами.
