# Подключение каталога — #30

Реализованы GET /api/tours и GET /api/tours/{tour_id}; обе операции отмечены implemented в OpenAPI. Типы — TourOffer и TourOfferPage из сгенерированного контракта. API доступен manager/head независимо от наличия заявок; бухгалтер получает 403, запрос без входа — 401.

## Список и фильтры

GET /api/tours возвращает {items, page, page_size, total}, только активные предложения. Все заданные фильтры применяются совместно:

| Параметр | Значение |
|---|---|
| destination | Подстрока направления без учёта регистра; крайние пробелы очищаются. % и _ — буквальные символы |
| starts_from | Начало тура не раньше даты YYYY-MM-DD, включительно |
| ends_until | Окончание тура не позже даты YYYY-MM-DD, включительно |
| tourist_count | Точное число туристов, целое от 1 до 2147483647 |
| max_price | Максимальная общая цена строкой с двумя знаками, например 120000.00; допускается 0.00 |
| sort | price (по умолчанию), -price, starts_on; при равенстве добавляется id в том же направлении |
| page, page_size | Страница с 1 (максимум 2147483647), размер 1–100, по умолчанию 20 |

Не передавать незаполненные фильтры. Пустые destination, даты и цена, неизвестные параметры, неверная сортировка, отрицательная цена и ends_until раньше starts_from дают 422 в едином формате Error. Пустой результат и страница за пределами списка дают 200, items=[]; total учитывает фильтры и активность.

Пример для заявки из примеров контракта: /api/tours?destination=Сочи&starts_from=2027-06-01&ends_until=2027-06-08&tourist_count=2&max_price=120000.00. Даты задают границы тура, а не пересечение с указанным интервалом. Цена — за всех указанных туристов, не за одного; не умножать её на tourist_count.

## Карточка

TourOffer содержит id, title, destination, starts_on, ends_on, tourist_count, supplier, services, price, currency=RUB, is_active и version. services — список строк, может быть пустым. Цена передаётся строкой; не преобразовывать её во float для бизнес-расчётов. Неактивный и отсутствующий тур дают одинаковый 404, неверный UUID — 422.

Создания, изменения и удаления туров через HTTP в MVP нет. Idempotency-Key для чтения не нужен. Выбор тура и публикация подборки относятся к #31: сейчас каталог не меняет статус или содержимое заявки. Следующая задача должна сохранять снимок предложения, а не только ссылку на изменяемый каталог.

## Демо-данные и хранение

Миграция 0004_tour_catalogue создаёт tour_offers. При SEED_DEMO=true bootstrap/seed добавляет восемь вымышленных предложений на июнь–июль 2027: Сочи, Анталья, Казань, Алтай и Санкт-Петербург. Есть разные даты, количества туристов, цены и услуги; для примера заявки Сочи 01–08 июня 2027 на двоих есть подходящее предложение.

Seed использует постоянные UUID, повторный запуск не создаёт дубли и не возвращает прежние цены/активность изменённым предложениям. При SEED_DEMO=false каталог остаётся без демонстрационного наполнения. Цена numeric(14,2), даты, количество, валюта, версия и состав услуг проверяются ограничениями PostgreSQL. Состав услуг хранится как text[], нормализованное направление — отдельное внутреннее поле для поиска; они не меняют HTTP-контракт.
