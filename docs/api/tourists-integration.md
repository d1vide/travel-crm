# Подключение туристов — #32

Реализованы пять операций OpenAPI: выдача ссылки формы, публичные GET/PUT формы и служебные GET/PUT списка туристов. Форматы Tourist, TouristSubmission, TouristSubmissionItem, TouristSubmissionResult и PublicTouristForm уже входят в сгенерированный контракт. Паспортные данные доступны только ответственному менеджеру и руководителю; бухгалтер получает 403, чужая и отсутствующая заявка — одинаковый 404.

## Список и редактирование сотрудником

GET /api/requests/{request_id}/tourists возвращает массив Tourist в порядке последней отправки. У каждого туриста есть id, request_id и version. Пустой список — []. Запрос не имеет пагинации. Ответы с документами защищены Cache-Control: no-store и Referrer-Policy: no-referrer.

PUT /api/requests/{request_id}/tourists принимает TouristSubmission: request_version и полный tourists. Каждый элемент содержит обязательные id (null для нового), full_name, birth_date, document_type, document_number, document_expires_on (nullable). Передавать входную модель, не read DTO с request_id/version. Поля банковских карт и другие неизвестные поля отклоняются.

Список должен быть непустым и точно соответствовать tourist_count заявки. ФИО и номер документа очищаются от крайних пробелов, пустые значения запрещены. Даты — YYYY-MM-DD; дата рождения не в будущем по Москве. document_type — passport/international_passport; у загранпаспорта обязателен document_expires_on. Дополнительных требований к формату номера или сроку относительно поездки сейчас нет.

Переданный id должен принадлежать текущему списку этой заявки; чужой, неизвестный и ранее удалённый id дают 404. Повтор одного id внутри массива — 422. Для сохранения туриста передать его id; id=null создаёт новую запись. Пропущенные туристы удаляются из текущего состава. Их архивные строки сохраняются для исторических связей будущих броней и больше не редактируются через эту форму.

Операция атомарна. Каждая новая принятая команда увеличивает version заявки на 1. version туриста начинается с 1 и увеличивается при изменении его данных или позиции. Ответ — только accepted_count и request_version; после сохранения перечитать Request и служебный список. Не вычислять UUID или следующую версию самостоятельно.

## Публичная форма

POST /api/requests/{request_id}/tourist-link без тела выдаёт 201 PublicLink с purpose=tourists. Ссылка действует 7 дней, каждый выпуск отзывает предыдущую. origin берётся из PUBLIC_APP_URL; маршрут страницы — /public/tourist-forms/:token, API — /api/public/tourist-forms/{token}. Копировать url из ответа. В карточке Request.tourist_link доступны только id, purpose, expires_at, is_active. Сырой url повторно не выдаётся.

Команда выпуска не принимает Idempotency-Key и не должна повторяться автоматически при сетевой ошибке или refresh. При потере ответа предложить явный перевыпуск. DELETE /api/public-links/{link_id} отзывает ссылку, повтор возвращает 204. Выпуск и отзыв не меняют версию заявки. Неверный, истёкший, отозванный токен и токен другого назначения дают одинаковый 404. Переназначение менеджера сохраняет ссылку, но прежний менеджер теряет доступ к документам и повторным командам.

GET формы не требует JWT и возвращает только tourist_count, request_version, expires_at, is_editable, closed_reason. Ранее введённые имена, документы, UUID туристов и идентификаторы заявки не возвращаются. Форму нужно строить пустой; после повторного открытия пользователь вводит полный список заново с id=null. Для редактирования с сохранением UUID сотрудник использует защищённый GET.

PUT публичной формы принимает тот же TouristSubmission и отвечает TouristSubmissionResult. После успешной отправки показывать подтверждение, без персональных данных. Для исправления клиент перечитывает GET формы и отправляет полный список с актуальной request_version; нельзя автоматически заменять версию при конфликте.

Форма редактируется только в in_progress/offer_prepared. Для действительной ссылки при закрытой форме GET возвращает 200 с is_editable=false и closed_reason, новая отправка — 409 tourist_form_closed. Недействительная ссылка всегда даёт 404. Cancel/resume/return-to-work отзывают ссылки; новая подборка не отзывает форму туристов. Сохранённые туристы остаются в заявке при отмене и возврате в работу.

## Повторы, ошибки и защита данных

Оба PUT требуют Idempotency-Key UUID. Повтор после сетевой ошибки или refresh сохраняет исходные тело и ключ. Успешный повтор возвращает исходные accepted_count/request_version без новых строк и повышения версии, даже если текущая версия заявки уже изменилась. Сначала проверяются актуальные права сотрудника либо активность ссылки. Другой body с тем же ключом — 409 idempotency_conflict; новая команда со старой request_version — 409 version_conflict. Новый ключ назначается только новому намерению пользователя. Неуспешные команды не запоминаются.

422 содержит fields с путями вида tourists.1.document_expires_on; ошибка количества/повторного id относится к tourists. Ошибки не повторяют введённые значения. В идемпотентности сохраняются хеш тела, безопасные счётчик/версия и ID ссылки; сырого токена, имён и документов там нет. Паспортные данные не входят в аудит.

Все публичные ответы, включая ошибки, имеют no-store/no-referrer; nginx и сервер маскируют публичные URL в журналах. Не сохранять документы или токен в localStorage, аналитике, диагностике и сторонних ресурсах страницы. В Compose PostgreSQL настроен без записи SQL, параметров и DETAIL ошибочных строк; при отдельном запуске PostgreSQL сохранить log_error_verbosity=terse, log_min_error_statement=panic, log_statement=none, log_min_duration_statement=-1. Внешние прокси и мониторинг должны соблюдать те же ограничения.

## Проекции и следующий модуль

Request.tourists_received — число текущих туристов, tourist_form_editable — доступность редактирования, tourist_link — метаданные последней ссылки (после отзыва/истечения is_active=false). allowed_actions включает edit_tourists и issue_tourist_link только при редактируемой форме. Количество и метаданные для списка заявок собираются пакетно.

В #14 необходимо дополнить общий tourists.views.is_editable проверкой действующей брони, включая pending_confirmation. Та же проверка должна закрыть публичные и служебные записи, выдачу ссылки и allowed_actions. GET действительной ссылки при этом сохраняет безопасный шаблон закрытой формы. При создании/подтверждении брони проверяются число туристов заявки и снимка тура; Booking.tourists получает отдельные неизменяемые снимки. До #14 active_booking остаётся null и create_booking не предлагается.

Миграция 0007_tourists добавляет таблицу tourists с position и removed_at для текущего порядка и архива. Запись сериализуется в порядке ключ повтора → Client → Request → PublicLink (для публичной формы); после ожидания ссылка перепроверяется на отзыв и истечение. Версия заявки, туристы и безопасный результат повтора коммитятся вместе.
