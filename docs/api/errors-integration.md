# Валидация и ошибки — #18

Сервер проверяет ввод независимо от интерфейса. Контракт ответа ошибки остаётся `{code, message, fields: [{field, message}]}`. Новых полей или несовместимых типов нет; общие ответы и пример вложенной ошибки находятся в openapi.json.

## Поля и формы

422 validation_error означает ошибку входных данных. message — общее русское сообщение, fields — конкретные поля. field использует имена JSON: budget, amount, version, request_version, date_to, tourists.0.birth_date. Индекс туриста начинается с нуля. Не разбирать английский текст Pydantic и не сопоставлять ошибки по введённому значению.

Обязательное поле сохраняет сообщение «Обязательное поле», лишнее — «Неизвестное поле», включая лишние amount/phone в неподходящей форме. Для отрицательных бюджетов и неверного формата денег, неположительных оплат/возвратов, числа туристов, версий, дат и UUID выдаются отдельные русские подсказки. Порядок дат, будущая дата рождения и срок загранпаспорта проверяются серверными схемами. Подробности количества туристов, выбранного тура и финансовых лимитов повторно проверяются в бизнес-команде.

Повреждённый JSON даёт field="body"; показывать общую ошибку формы. Ошибки параметров, пути и заголовков также используют fields. В сообщениях нет исходного JSON, паспортов, паролей, токенов, SQL и технических исключений. Не записывать чувствительное тело команды в клиентские журналы для диагностики ошибки.

## Статусы и повтор

| HTTP / code | Действие интерфейса |
|---|---|
| 400/422 validation_error | Показать ошибки полей/формы, дать исправить ввод |
| 401 unauthorized | Использовать существующий refresh; при неуспехе перейти на вход. WWW-Authenticate: Bearer |
| 403 forbidden | Показать отсутствие доступа; не повторять refresh бесконечно |
| 404 not_found | Запись отсутствует или недоступна; не раскрывать чужие идентификаторы |
| 405 not_found | Метод недоступен; сервер сохраняет Allow |
| 409 version_conflict/invalid_transition и остальные конфликты | Перечитать ресурс, показать актуальные действия; не менять version локально |
| 429 rate_limited | Предложить повторить позже; учитывать Retry-After, если он выдан |
| 500/503 server_error | Показать общую ошибку сервера/недоступность БД без технических деталей |
| 501 not_implemented | Операция пока недоступна |

Все ошибки no-store/no-referrer. fields может быть пустым — тогда требуется сообщение уровня формы. Сервер не отражает произвольный detail HTTPException или внутренние заголовки. Для сетевого сбоя без HTTP-ответа используется существующий клиентский network_error; такой сбой не подтверждает и не отменяет денежную операцию. Повтор бизнес-команды сохраняет исходные тело и Idempotency-Key; новое исправленное действие получает новый ключ.

В текущем фронтенде ApiError/fieldMessages уже читают этот формат. Привязка всех новых полей к сообщениям, проверки форм, редирект с истёкшей сессией и приёмка интерфейса остаются фронтенд-критериями #18; готовность серверного обработчика их не заменяет.
