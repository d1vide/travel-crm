## Совместная ответственность


Оба участника согласуют ТЗ, архитектуру, контракт API и критерии приёмки, актуализируют документацию и проверяют сквозные сценарии. Тимлид координирует работу; каждый отвечает за качество своей части. Проверки интерфейса выполняются совместно.


## Порядок работы


1. Задача описывается в Issue: цель, объём, исполнитель и проверяемые критерии готовности.
2. Для изменения создаётся отдельная ветка, например docs/project-setup, feature/clients или fix/booking-status.
3. Изменения сохраняются понятными коммитами, связанными с задачей.
4. Pull Request содержит описание результата и способ проверки; второй участник по возможности проводит ревью. До подключения второго участника автор выполняет самопроверку и отмечает это в PR.
5. После проверки изменения объединяются в main; Issue закрывается по выполненным критериям, документация обновляется при изменении поведения.


## Готовность задачи


Выполнены критерии Issue; изменения проверены подходящим способом; связанные документы актуальны; код не содержит секретов и реальных клиентских данных; результат доступен в main.


GitHub-приглашение @Alex-kholod отправлено. Для получения доступа необходимо принять приглашение. Распределение работ может уточняться по договорённости команды с отражением в Issues и этом документе.



## Настройки репозитория

Владелец и соавтор с правом записи могут создавать коммиты непосредственно в main. Обычные изменения рекомендуется оформлять через отдельную ветку и Pull Request; одобрение второго участника доступно, но не обязательно. Force push и удаление main заблокированы.
