# Приёмочный прогон — 26.11.2026

Сценарий: десять шагов из раздела 7 [ТЗ](technical-specification.md), задача [#19](https://github.com/d1vide/travel-crm/issues/19). Указание «семь шагов» в первоначальном описании задачи устарело.

**Результат: частичная приёмка.** Основной путь до полной оплаты, уведомления, сохранение истории после перезапуска и отмена проверены через браузер. Возвраты, отчёт и часть возможностей руководителя проверены через API, но соответствующие экраны ещё не подключены. Это не заменяет ручную приёмку этих экранов; #19 остаётся открытой.

## Окружение и границы

- База: main `67a3050b0be52b5a275b1682a8b191609a9ee967` (включая интерфейсы PR #63 и серверные PR #64–66), затем исправление оплаты `ecb0456`.
- Windows, PostgreSQL 16, backend и платёжная HTTP-заглушка, production-сборка фронтенда за нативным nginx. Сервисы запущены локально с теми же маршрутами проксирования, что в `frontend/nginx.conf`.
- Для каждого прогона выделены отдельные случайные схемы тестовой БД. Только вымышленные клиенты, туристы, документы и тестовые платежи; ссылки доступа и учётные данные в отчёт не включены.
- Проверялся встроенный браузер Chromium. Отдельная проверка Firefox и запуск Compose на чистой машине не выполнены; последний остаётся в #24. Нативный запуск не подтверждает сборку контейнеров.
- Перезапуск backend и заглушки выполнен с сохранением той же БД; nginx и браузер продолжили работать.

Причина #67 соответствует алгоритму [Fetch: добавление Origin](https://fetch.spec.whatwg.org/#append-a-request-origin-header). Исправление не разрешает отсутствующий, `null` или посторонний Origin. Ошибка сети/HTTP выводится как ошибка, без ложного сообщения об успехе.
